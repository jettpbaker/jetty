# M4: bot search

Every bot has `search_wiki` over its own wiki home and `search_threads` over its
chat and workers' threads. Both use case-insensitive keyword search: whole words
and prefixes ranked with BM25. Try a few wordings with specific names, codes or
terms from the original text. Search does not infer related meanings.

The descriptions, input and result types, default k=5, maximum k=20 and query
length cap live in `shared/src/bot-search.ts`. The prompt guidance is in
`server/src/bot-prompt/lookups.md`. These always-loaded, approval-free MCP tools
are bot-only; workers and ordinary user threads do not have them. Results go to
the bot's agent, without crossing the client wire or appearing as bot chat tools.

## Indexing and ranking

Search runs in the server process. There is no model, download, readiness wait,
self-check or search child. Calls serialize per bot, including wiki and thread
calls made together. Different bots have separate indexes and queues.

Indexes are disposable caches at
`JETTY_HOME/search/<botId>.keyword-v1.sqlite`, outside the bot's writable home.
Change the filename version when the schema changes and rebuild from source;
do not migrate a search cache. The earlier `<botId>.sqlite` files are unused.

Wiki search hashes eligible text files under `pages/`, `log/` and `files/`, plus
`brief.md`, `index.md` and `preferences.md`. It skips binaries and symlinks,
chunks changed files with the prose/code-aware chunker, and removes deleted
files. Results carry relative paths, line ranges, text and scores.

Thread search covers the bot chat and every worker with that bot ID, including
archived threads. It excludes foreign bots, ordinary user threads, private notes,
streaming assistant messages, subagents, worker reports and self-wake messages.
It also excludes messages in the caller's current turn to avoid self-retrieval.

Sequence cursors persist per thread. Unchanged threads require no item reads.
For changed threads, store events after the cursor identify affected items;
search reads their current content, replaces their chunks, and advances the
cursor. New caches read the initial state once. Old unsplit snapshots may also
need a full-state fallback. Messages that become blank or private lose their
cached chunks. Turn completion catches messages that were still streaming at
the previous search.

Both tools rank whole-word and lower-weight prefix matches, discard zero-score
chunks and return squashed BM25 scores rounded to three places. Thread ties
prefer the most recent message, then stable IDs. Wiki ties prefer recently modified files, then path and line.
Returned thread titles and assistant authors use current metadata, without
loading full hit threads. Other authors and bot-stamped dates are cached with
the message. Hits include thread/message IDs and worker deep links; archived
hits include `archived: true`. Older results may since have changed.

## Verification

Use an isolated `JETTY_HOME` with `JETTY_AGENT=echo`. Never use the real Jetty
home for benchmarks. Measure a first search, a search after most workers change,
and an immediate repeat, for threads and wiki. Compare specific terms, mixed
case, partial words and an absent term, and inspect top results. Existing search
and MCP tests cover incremental indexing, binary exclusion, scope, result
shape and tool registration. No new tests are needed for removing the model.

The original M4 acceptance records are in git history. The current integration
record is `m4-integration.md`; implementation notes are in `m4-server-build.md`.
