## Acceptance checks

1. A bot's own pending approval appears in its chat as Paper approval card B,
   beneath its bubble, or on its own during a background turn. Its title is the
   Bash description, otherwise the action's summary. Show the command beneath.
2. Deny is on the left; Allow always and Allow once are on the right. Allow once
   uses the bot's face colour. Deny has no note field; the composer stays available.
3. Each decision immediately collapses the card to one muted row with a stroked
   tick, decision and command. No user bubble echoes the decision. A withdrawn
   request cannot still be answered.
4. Allow always stores a plain-English rule on this bot, worded from the action's
   description and the command prefix Claude suggests ("Close the two v16 issues with
   `gh issue close`"); other tools get a short summary ("Write files in its home",
   "Fetch pages from docs.stripe.com"), never their raw input. Claude reads each rule
   as "Forge may close the two v16 issues with `gh issue close`". Never send Claude's
   suggested permission rules back to the provider or write them into project/user
   permission settings.
5. Pass bot rules to Claude as `settings.autoMode.allow`, with `"$defaults"` first,
   at session start. Apply additions and removals to a live session through
   `applyFlagSettings`, including resetting to `["$defaults"]` after the last removal.
6. The bot settings sheet contains Paper rules B's Always allowed table: rule,
   source action or “Written by you”, date, remove button, inline plain-English
   add field, and “Saved from Allow always. Only used while Full access is off.”
   Rules survive reconnect/restart and do not affect another bot or its workers.
7. AskUserQuestion uses Paper question card A, with title, Dismiss, option rows
   (label and description), and Other. A single choice answers immediately;
   multiple choices or custom text can be submitted. Support all questions in a
   request and preserve unfinished choices while switching chats.
8. Answered question cards stay in history, muted, showing only selected answers
   with a stroked tick and their descriptions; dismissal also stays in history.
   Answering creates no user-message echo. The bot's waiting state clears when no
   own question/approval or worker approval remains.
9. Bot Agent/Task calls at max effort are refused with exactly
   `max isn't available to bots; use xhigh`, including Full access. Existing
   list_models/create_thread max restrictions remain intact.
10. Worker approvals stay in the worker's thread. The bot links them; no worker
    approval card is copied into its chat.
11. Check dark and light rendering against Paper. Use free ports and a temporary
    JETTY_HOME, never ports 5173/8787/5174 or the real Jetty home.
12. `bun run typecheck`, `bun run lint`, `bun run format:check` and `bun test` pass.

## Integration notes

Rules use bot-specific keys in the existing settings store, avoiding a migration
number shared with parallel M2/M4 work. `bot.setAllowRules` updates only those rules.
The settings shell's existing model/full-access features are visible but disabled;
M3 only wires the Always allowed table. New components translate the Paper card
and table layouts to the repo's tokens and primitives; there is no matching card
or settings implementation in the sketchpad.

No parked prompt lines belong to tools landed by M3: all six waiting lines cover
quiet/read-only/wait/setup workers or search (M2/M4). Prompt files remain verbatim.
The Agent max-effort refusal already existed on this branch and is preserved.
